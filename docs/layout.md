## Загрузка проекта в OpenROAD

3. В командной строке OpenROAD запустите команду:

```tcl
source ../../scr/layout/load_design.tcl
```

Произойдет исполнение скрипта load_design.tcl, имеющего следующее содержание:

```tcl
############################################################################################
#set units
set_cmd_units -time ns -capacitance pF -current mA -voltage V -resistance kOhm -distance um
############################################################################################

############################################################################################
#Read LEF files
read_lef ../../lefs/sky130.tlef ; # Techlef

read_lef ../../lefs/sky130_fd_sc_hd.lef ; # load all cell lefs
############################################################################################

############################################################################################
# Define corners and read corresponding LIB files
define_corners fast typical slow

read_liberty -corner fast    ../../lib/sky130_fd_sc_hd__ff_n40C_1v95.lib
read_liberty -corner typical ../../lib/sky130_fd_sc_hd__tt_025C_1v80.lib
read_liberty -corner slow    ../../lib/sky130_fd_sc_hd__ss_100C_1v40.lib
############################################################################################

############################################################################################
# Read the netlist
read_verilog ../syn/segment_seconds_netlist.v
link_design seven_segment_seconds
############################################################################################

############################################################################################
# Read SDC file
read_sdc ../../scr/sdc/const.sdc
############################################################################################
```

Данный скрипт задает некоторые начальные настройки, а затем последовательно загружает LEF  и LIB файлы, полученный после логического синтеза нетлист, а также SDC файл. Несколько LIB файлов позволят выполнить статический временной анализ с учетом PVT вариаций.

**Построение сетки земли-питания**

В технологии Skywater доступно 5 слоев металлизации. Мы проектируем блок, который может быть интегрирован в более крупную схему, поэтому исключим использование верхнего пятого слоя, так как в нем может выполняться включение блока в сеть питания кристалла на верхнем уровне. В силу небольших размеров блока ограничим сетку четвертым и первым слоем, в котором происходит непосредственно подключение стандартных ячеек к системе питания.

8. Запустите скрипт генерации сетки земли-питания, выполнив в терминале OpenROAD команду:

```tcl
source ../../scr/layout/pg_net.tcl
```

Содержание данного файла представлено ниже:

```tcl
#######################################################################
#Make connections
add_global_connection -net VDD -pin_pattern "vdd" -power
add_global_connection -net VSS -pin_pattern "gnd" -ground

global_connect

set_voltage_domain -name Core -power VDD -ground VSS
define_pdn_grid -name Core -voltage_domain Core
#######################################################################
#Add stripe
add_pdn_stripe -layer met4 -width 0.9 -offset 0.45 -pitch 3.6 -grid Core
add_pdn_stripe -layer met1 -width 0.28 -followpins -grid Core

add_pdn_connect -layers {met1 met4} -grid Core
#######################################################################
#Actual creation of PG grid
pdngen
#######################################################################
```

Первый блок команд создает глобальные соединения проекта, т.е. сопоставляет пины земли-питания элементов с сеткой земли-питания.
Второй блок определяет параметры будущей сетки с помощью команды `add_pdn_stripe`. Наконец, команда `pdngen` выполняет построение сетки земли-питания.

**Размещение физических ячеек**

Физические ячейки необходимы для выполнения определенных технологических требований, обеспечения надежности. В работе мы будем использовать следующие типы физических ячеек:

- Well-tap ячейки - обеспечивают подключение p-подложки к земле и n-кармана к питанию для предотвращения эффекта защелки. Well-tap размещаются по площади кристалла в шахматном порядке с заданным интервалом. В данном проекте интервал составляет 13 мкм;
- End-cap ячейки - размещаются в конце рядов стандартных ячеек, так как из-за определенных технологических факторов они не должны завершаться логическими ячейками;
- Filler ячейки - устанавливаются в участки кристалла, не занятые логическими ячейками или макроблоками, т.е. заполняют свободное место на кристалле для сохранения непрерывности областей легирования и шин питания в нижнем слое металлизации. Некоторые ячейки типа filler также содержат емкость для фильтрации помех в цепях земли и питания.

11. Filler ячейки размещаются на последнем этапе разработки топологии. Для запуска размещения Well-tap и End-cap ячеек запустите в OpenROAD команду:

```tcl
source ../../scr/layout/taps.tcl
```

Данный скрипт расставит нужные ячейки, а также сохранит DEF файл проекта `fp.def`, так как на данном этапе будет завершена разработка floorplan.

## Синтез дерева тактовых сигналов

15. Для запуска синтеза дерева тактовых сигналов выполните команду:

```tcl
source ../../scr/layout/cts.tcl
```

Наиболее важными командами в процессе синтеза дерева тактовых сигналов являются:

```tcl
# Список используемых при CTS буферов
set ckbuf_list "sky130_fd_sc_hd__clkbuf_1 sky130_fd_sc_hd__clkbuf_2 sky130_fd_sc_hd__clkbuf_4"

# Буфер, используемый в качестве корня дерева тактовых сигналов
set root_ckbuf_list "sky130_fd_sc_hd__clkbuf_8"

# Синтез дерева тактовых сигналов на основе определенных выше ячеек
clock_tree_synthesis -buf_list $ckbuf_list -root_buf $root_ckbuf_list
```

Команда `clock_tree_synthesis` имеет большое количество дополнительных настроек, которые не являются необходимыми для данного проекта, но с которыми можно ознакомиться в документации САПР.
Помимо этого, скрипт содержит настройки, определяющие оценку паразитных параметров, и другие вспомогательные команды. Результат сохраняется в файл `cts_opt.def`.

![](images/clock_tree.png)

Слева от кнопки Update находится раскрывающийся список со значением fast. В этом списке отображаются используемые в проекте "углы" (англ. corner), которые были заданы при загрузке начальных данных в OpenROAD. ## Трассировка межсоединений

20. Для запуска трассировки межсоединений выполните приведенную ниже команду. Обратите внимание, что трассировка является самым ресурсозатратным этапом данного маршрута и может выполняться до нескольких минут в зависимости от мощности вашего компьютера.

## Завершение разработки топологии

22. Для завершения разработки топологии блока необходимо заполнить свободное от ячеек место специальными физическими ячейками - филлерами (filler). Они обеспечивают непрерывность областей легирования и шин питания в нижнем слое металлизации. Запустите скрипт `finish.tcl` в OpenROAD:

```tcl
source ../../scr/layout/finish.tcl
```

Помимо заполнения блока филлерами, данный скрипт выпишет также финальный DEF файл `final.def`, который будет использоваться для дальнейшей генерации GDS.

## Анализ характеристик блока

По завершении разработки топологии и перед генерацией финального GDS получим основные характеристики разрабатываемого цифрового блока, а именно: потребляемую мощность, быстродействие, площадь.

24. Для вывода оценки потребляемой мощности в терминале OpenROAD выполните команду:

```tcl
report_power -corner fast
```

В результате в терминал будет выведена таблица анализа мощности для "угла" fast. Пример таблицы приведен на рисунке ниже.

![](images/power_report.png)

Каждая строка отвечает за определенную категорию элементов. Например, элементы последовательностной логики (Sequential). В свою очередь по столбцам происходит разделение на внутреннюю мощность (Internal Power), мощность переключения (Switching Power) и мощность утечки (Leakage Power).

```tcl

```

В результате в терминал будут выписаны 2 отчета о статическом временном анализе. Пример отчета приведен ниже:

![](images/sta_report.png)

Обратите внимание на строчки `Path Type: min/max`, а также `slack` (нижняя строчка на рисунке).

- `Path Type: min` отвечает за анализ времени удержания (hold check);
- `Path Type: max` отвечает за анализ времени установки (setup check).

Если после `slack` следует `(MET)`, это означает, что временные ограничения для показанного пути выполнены. Проверьте результаты для обоих типов путей.
